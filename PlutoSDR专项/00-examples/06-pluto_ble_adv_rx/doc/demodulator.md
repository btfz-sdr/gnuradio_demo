# BLE 广播包接收解调链（ble_phy.c）设计说明

对象：`ble_phy.c` / `ble_phy.h`，LE 1M PHY 广播包（信道 37/38/39）的纯 C 解调器。
目标：在 PlutoSDR（Zynq-7010）上实时跑，access code 一次命中即 100%（error = 0/40）。

相关文档：
- `doc/gnuradio-gfsk-demod.md` —— GNU Radio 参考实现的确切参数/公式，以及为什么不能 1:1 照搬
- `skills/pluto-ble-adv-rx/SKILL.md` —— 操作手册（排查流程、上机注意事项、环境坑）

---

## 1. 处理链

```
I/Q(int16)
  → 正交鉴频     d = atan2(i*prev_q - q*prev_i, i*prev_i + q*prev_q)
  → 匹配滤波     长度 = sps（10 MHz → 10 点）滑动求和，1 符号积分
  → 判决         x[n] > 0 → 1
  → 10 个定时相位并行 40 bit 窗口（相位 = 样点序号 % sps）
  → AA 汉明距离 ≤ 3 判为候选 → 逐字节收 PDU → 解白化 → CRC-24 校验
```

注意：链路上**没有** DC/频偏扣除（原因见 §2.3），也没有时钟恢复环（见下面第 2 点）。

对应 GNU Radio 的 `digital.gfsk_demod` = `quadrature_demod_cf` →
`clock_recovery_mm_ff` → `binary_slicer_fb`，但有 **两处刻意的不同**：

1. **加了一级 1 符号匹配滤波（积分清零）。**
   这是 FSK 接收的匹配滤波器：每符号平均 sps 个样点。10 Msps 采样、
   1 Msym/s 符号率时，判决前的一次平均等于白捡约 10 dB Eb/N0。
   旧实现直接拿"一个样点"的鉴频输出判决，噪声按 5 MHz 级带宽进来，误码极高。

2. **定时恢复改成前馈全相位并行，不用反馈环。**
   每个样点只把 1 bit 推进"相位 = 样点序号 % sps"那一个窗口，只比较那一个窗口，
   所以代价是 O(1)/样点，和旧版单相位硬搜索同量级，但覆盖了全部相位空间。
   反馈环（GR 的 Mueller&Muller）有两个问题在 BLE 上很致命：
   - 8 个符号的前导码太短，环收敛不了；
   - 环在"眼图交叉点"上还有一个稳定平衡点，实测会锁在那里
     （软判决幅度只剩 ±0.16，而正确采样点是 ±1.5）。
   本工程在真实空口数据上实测过这两点，所以不做环。

## 2. 定位到的四个问题（都已修）

### bug 1：access code 比特序反了 —— "40/40 永远不可能"

BLE 的 access address `0x8E89BED6` 是 **LSB 先发**，所以空中 32 bit 的顺序是
`0xD6, 0xBE, 0x89, 0x8E`（每字节内部还是 LSB 先出）。

旧代码把字节按书写顺序 `0x8E, 0x89, 0xBE, 0xD6` 拼成 40 bit 模板，
等于拿反过来的地址去相关：**任何真实包最多只能落在随机水平（~20/40）**，
即使解调器完美也永远到不了 40/40。这就是"只能 32/40"的一半原因。

修法：直接按 32 bit 数值 LSB-first 展开，不要再手工排字节。

```c
const uint32_t aa = 0x8E89BED6u;
for (int b = 0; b < 32; b++) v |= (uint64_t)((aa >> b) & 1u) << (39 - k++);
```

同一处字节序错误也出现在 CRC 的输出上：CRC-24 的 3 个字节是
`swap(MSB), swap(mid), swap(LSB)`（`swap` = 字节内比特反转），不是 LSB-first。

### bug 2：解调链本身

旧链：单样点鉴频 → 一个写错的 3 点递归 IIR（`hist[3] = (h2+h3+ac)/3`，
把输出又喂回输入，极点 0.768 / -0.434；`hist[0]`/`hist[1]` 从来没被读过）
→ M&M 环（`mu += 1/omega`、增益 0.08/0.0005，都不是 GR 的参数；插值方向还反了）。

实测：把旧算法喂真实空口录波，257801 个判决 bit 里 AA 距离最高 34/40，
≥32 的有 16 个 —— 与"随机比特"的理论期望（23 个）一致，即输出完全是噪声。
而同一段原始 IQ 的真实信号是干净的（匹配滤波后 AA 精确 40/40、软幅度 ±1.5）。
结论：问题在解调器，不在射频、不在增益。

### 问题 3：AA 命中的相位 ≠ 能把 PDU 解出来的相位（漏包主因）

原实现一旦 AA 命中就 `s_collect = 1`，并在收包期间**跳过 AA 搜索**（`continue`），
等于**无条件采纳最先越过门限的那个相位的判决结果**。

逐包把 10 个定时相位都试一遍后的量化真相（2.1 s 真实录波）：

- 40 bit 的 AA 对采样时刻**不敏感**（判断裕量大），后面 ~300 bit 的 PDU **不是**；
- 同一个真实包**平均只有 4.9/10 个相位**能通过 CRC —— 其余相位 AA 误差同样是 0，
  但 PDU 里错 1~2 bit，CRC 必挂；
- 只认最先命中的那个相位 ≈ 按 5/10 的概率抽签，抽错就丢包。

修法（`ble_phy.c` 第 5、6 步）：**每个定时相位各起一路收包**。
AA 在哪个相位命中，就在那个相位上独立累计 PDU 位；谁先过 CRC 谁算数。
同一包会有多路同时成功 → 报告端按样点位置去重（100 样点内只报一次，
真实 BLE 包至少 88 符号 = 880 样点，不可能吃掉隔壁的包）。
每路 = 40 bit 窗口 + 384 bit 缓冲，10 相位合计约 4 KB，每样点仍只有一次移位。

效果：同一批录波 **ch37 16→18、ch38 7→23、ch39 16→47**
（独立 Python 参考实现是 18/18/36 —— 它每个位置只试一个相位，所以它自己也漏包，这一项 C 端反超）。

### 问题 4（曾经加过又删掉）：DC/频偏扣除 —— 实测有害

动机：有一次抓包里鉴频输出带 0.086 rad/样点（≈137 kHz）的偏置，
和 ±250 kHz 的 BLE 频偏同量级，当时用"门控慢速 DC 跟踪"（只喂 `|d| < 0.5 rad`
的样点，时间常数 13 ms）确实让那一段 0.26 s 录波从 0 包变成 2 包。

但在 2.1 s 录波上量化后发现它**整体有害**：

- 跟踪器收敛到的是**噪声的不对称性**（实测 −0.061 rad/样点），
  而包所在处的真实偏置约 0（原始鉴频输出在包内本身就围绕 0，软幅度 ±1.5 居中）；
- 扣掉这个"噪声偏置"等于把眼图整体平移 0.6（信号只有 ±1.5），弱符号成片翻错：
  同一段录波 **门控 DC 6 包 vs 不扣 DC 16 包**（独立参考 18 包）；
- 全 6 段录波合计：门控 DC 35 包 vs 不扣 DC 45 包。

结论：**链路不做 DC 扣除**，与 GNU Radio / 参考实现一致。
真正出现"眼图整体偏在某一侧"时先查增益（削顶会产生真实的鉴频偏置），不要用盲目估计器去补。

## 3. 实测结果

### 离线回放（真实空口录波，manual 增益 60 dB，10 Msps，各 2.1 s）

| 文件 | 本实现 | 独立 Python 参考实现 |
|---|---|---|
| ch37 | 18 包 | 18 包 |
| ch38 | 23 包 | 18 包 |
| ch39 | 47 包 | 36 包 |

都是 CRC OK，且**无重复报告**（同一 PDU 在 10 万样点内只出现一次）；
ch39 的 47 个包来自 8 个不同设备、包间隔中位数 3.8 万样点（≈3.8 ms，远大于一个包的长度）。
参考实现每个候选位置只试一个相位，所以它自己会漏包 —— 这一项本实现反超。

解出的包与独立参考逐字节一致，例如美的设备 `50:5E:3A:A8:35:3D`：
`20233D35A83A5E5002010606096D6964656112FFA806013232333936363739414331313639A15BA5`。

### 上机实时（PlutoSDR，fast_attack AGC，10 Msps，单信道）

| 信道 | 时长 | 收包 | 备注 |
|---|---|---|---|
| 37 | 16 s | 61 | 多个设备，无 refill 溢出 |
| 38 | 12 s | 25 | （旧版本实测）多设备（含 type 0x7） |
| 39 | 12 s | 24 | （旧版本实测）多设备 |

- `iio_buffer_refill` 无溢出报错 → Zynq-7010 实时余量够。
- 合成信号回归：**≥10 dB 出包，≤5 dB 不出**（这里的 dB 是"总带内 SNR"，
  经过匹配滤波 + 10 MHz→1 MHz 带宽折算，等效带内约 +20 dB）。

## 4. 参数与调优点（ble_phy.c 顶部）

| 宏 | 默认 | 说明 |
|---|---|---|
| `SAMPLE_PER_SYMBOL` | 10 | 每符号样点数，由 `ble_phy_set_sample_rate()` 从采样率推出 |
| `AA_ERR_MAX` | 3 | AA 接受门限（40 bit 里允许的错位数）。调大更灵敏、更易误报 |
| `AA_ERR_REPORT` | 2 | 打印候选的门限（诊断用） |
| `MAX_PDU_BYTES` | 48 | PDU 长度上限（ADV 最长 37，留扩展余量） |

链路里没有 DC 扣除宏（§2 问题 4 说明为什么删掉了）；
收包期间"更优候选接管"和"100 样点内报告去重"是固定行为，没有开关。
采样率不是 10 MHz 也能跑（`ble_phy_set_sample_rate(fs_mhz)` 会重算 sps 与滤波长度），
但 sps 越低匹配滤波增益越小，建议 ≥ 4。

## 5. 离线验证工作流（不需要反复上机）

```bash
# 抓一段原始 IQ（走网络 IIO，不用登录 Pluto；manual 增益避免削顶）
make capture CH=37 SEC=2 FILE=ch37.bin

# 用同一个 ble_phy.c 在宿主机回放（gcc 编译，带实时倍率统计）
make replay FILE=ch37.bin CH=37
```

`ble_replay.c` 与设备端共用同一个 `ble_phy.c`，所以离线结果可以代表设备端行为
（唯一差别是设备端分块喂 262144 样点，回放按同一块长喂）。

### 合成信号回归（不依赖空口，随时可跑）

```bash
python3 tools/gen_ble.py 30          # 生成 synth_snr30.bin（合成 BLE 广播包）
make replay FILE=synth_snr30.bin CH=37
```

当前基线：**≥10 dB 出包、≤5 dB 不出**（dB 是总带内 SNR，见 §3）。
改动解调器后跑这一条即可确认没有回退。
注意：加噪顺序是"先归一化信号再加噪"，不要在加噪后按总峰值归一化 ——
那样噪声会反过来改变信号电平，SNR 标签会出现非单调（曾经 10 dB 能解、20 dB 解不出）。
